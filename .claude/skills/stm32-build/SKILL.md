# STM32 项目编译与烧录

## 概述

STM32Cube VSCode 插件项目的通用编译与烧录 Skill。所有工具都位于 VSCode 插件的 bundle 目录中，**不在系统 PATH 中**，因此每次编译前需要从 CMakeCache.txt 自动发现工具链路径。

本 Skill 不包含任何项目路径或用户名等硬编码信息，可跨项目复用。

---

## 步骤 0：准备工作 — 动态发现所有路径

开始工作前，按顺序执行以下发现步骤。**每新开一个 bash 对话都需要重新设置 PATH**。

### 0.1 确定项目根目录

项目根目录 = 工作区根目录（`$PWD` 或对话中文档树的顶层目录）。

```bash
PROJECT_ROOT="/d/Personal_Files/STM32cubepjt/GUI_demo"  # ← 这里需要根据当前项目填写
cd "$PROJECT_ROOT"
```

**注意**：`PROJECT_ROOT` 是本文档中唯一的"运行时变量"，由对话上下文自然确定（用户打开的项目路径）。

### 0.2 从 CMakeCache.txt 发现工具链路径

工具链版本随 VSCode 插件更新变化，**禁止硬编码版本号**。一律从 CMakeCache 提取：

```bash
# 1) cmake 路径 — CMakeCache.txt 第 3 行注释中
CMAKE_PATH=$(head -3 build/Debug/CMakeCache.txt | grep "It was generated by CMake:" | sed 's/.*CMake: //')
CMAKE_BIN="$(dirname "$CMAKE_PATH")"

# 2) GCC 工具链路径 — 从 CMAKE_ADDR2LINE 反推
ADDR2LINE=$(grep "CMAKE_ADDR2LINE:FILEPATH" build/Debug/CMakeCache.txt | cut -d= -f2)
GCC_BIN="$(dirname "$ADDR2LINE")"

# 3) Ninja 路径 — 从 CMAKE_MAKE_PROGRAM 获取，失败则扫描 bundle
NINJA_PATH=$(grep "CMAKE_MAKE_PROGRAM:FILEPATH" build/Debug/CMakeCache.txt | cut -d= -f2)
if [ -z "$NINJA_PATH" ]; then
    BUNDLE_BASE="$(dirname "$(dirname "$(dirname "$(dirname "$(dirname "$CMAKE_PATH")")")")")"
    NINJA_PATH=$(ls -d "$BUNDLE_BASE/ninja/"*"/bin/ninja.exe" 2>/dev/null | sort -V | tail -1)
fi
NINJA_BIN="$(dirname "$NINJA_PATH")"

# 4) 加入 PATH
export PATH="$CMAKE_BIN:$NINJA_BIN:$GCC_BIN:$PATH"
```

### 0.3 发现 STM32CubeProgrammer CLI

CubeProgrammer 是独立安装的软件，路径不随项目变化。按以下优先级查找：

```bash
# 方法一：扫描常见安装位置（推荐，自动适配不同电脑）
CUBEPROG=$(find /c/ /d/ /e/ -maxdepth 4 -name "STM32_Programmer_CLI.exe" -type f 2>/dev/null | head -1)

# 方法二：如果方法一失败，手动检查这些常见路径
ls "/c/Program Files/STMicroelectronics/STM32Cube/STM32CubeProgrammer/bin/STM32_Programmer_CLI.exe"
ls "/d/STM32CubeProgrammer/bin/STM32_Programmer_CLI.exe"

# 方法三：如果找不到，报错并提示用户安装
echo "错误: 找不到 STM32_Programmer_CLI.exe。请安装 STM32CubeProgrammer。"
echo "下载地址: https://www.st.com/en/development-tools/stm32cubeprog.html"
```

### 0.4 发现 ELF 文件名

ELF 文件名写在各项目的 `CMakeCache.txt` 中（通常是项目名去掉空格），也可以直接从 build 目录 glob：

```bash
ELF_FILE=$(ls build/Debug/*.elf 2>/dev/null | head -1)
# 或从 CMakeCache 中读取 CMAKE_PROJECT_NAME
PROJECT_NAME=$(grep "CMAKE_PROJECT_NAME:STATIC" build/Debug/CMakeCache.txt | cut -d= -f2)
ELF_FILE="build/Debug/${PROJECT_NAME}.elf"
```

## 步骤 1：编译

完成步骤 0 的 PATH 设置后：

```bash
# 增量编译（Debug）
cmake --build build/Debug

# 全量重编译
cmake --build build/Debug --clean-first

# 编译 Release
cmake --build build/Release
```

编译成功后会显示 RAM/FLASH 用量：
```
RAM:   6216 B / 20 KB   (30.35%)
FLASH: 47504 B / 64 KB  (72.49%)
```

## 步骤 2：烧录

```bash
# 标准：烧录 + 校验 + 自动运行
"$CUBEPROG" -c port=SWD -w "$ELF_FILE" -v -g

# 仅烧录不运行
"$CUBEPROG" -c port=SWD -w "$ELF_FILE" -v

# 仅复位（不烧录）
"$CUBEPROG" -c port=SWD -rst
```

参数速查：

| 参数 | 作用 |
|------|------|
| `-c port=SWD` | 通过 ST-Link SWD 接口连接 |
| `-w <file>` | 烧录固件（支持 .elf / .bin / .hex） |
| `-v` | 烧录后校验 |
| `-g` | 烧录后自动运行程序，无需手动按复位键 |
| `-e` | 全片擦除（按需加在 `-w` 前面） |
| `-rst` | 软件复位 |
| `-hardRst` | 硬件复位（通过 nRST 引脚） |
| `--help` | 查看完整参数列表 |

`-g` 输出示例：
```
RUNNING Program ... 
  Address:      : 0x8000000
Start operation achieved successfully
```

## 步骤 3：一键编译+烧录（完整流水线）

```bash
# === 合并所有步骤 ===

# 0) 发现路径 + 设置环境
PROJECT_ROOT="/d/Personal_Files/STM32cubepjt/GUI_demo"
cd "$PROJECT_ROOT"

CMAKE_PATH=$(head -3 build/Debug/CMakeCache.txt | grep "It was generated by CMake:" | sed 's/.*CMake: //')
CMAKE_BIN="$(dirname "$CMAKE_PATH")"
ADDR2LINE=$(grep "CMAKE_ADDR2LINE:FILEPATH" build/Debug/CMakeCache.txt | cut -d= -f2)
GCC_BIN="$(dirname "$ADDR2LINE")"
NINJA_PATH=$(grep "CMAKE_MAKE_PROGRAM:FILEPATH" build/Debug/CMakeCache.txt | cut -d= -f2)
NINJA_BIN="$(dirname "$NINJA_PATH")"
export PATH="$CMAKE_BIN:$NINJA_BIN:$GCC_BIN:$PATH"

CUBEPROG=$(find /c/ /d/ /e/ -maxdepth 4 -name "STM32_Programmer_CLI.exe" -type f 2>/dev/null | head -1)
ELF_FILE=$(ls build/Debug/*.elf 2>/dev/null | head -1)

# 1) 编译
cmake --build build/Debug && \
# 2) 烧录 + 校验 + 自动运行
"$CUBEPROG" -c port=SWD -w "$ELF_FILE" -v -g
```

## 注意事项

1. **每新开一个 bash 对话都需要重新设置 PATH**，环境变量不跨对话保持
2. **工具链路径一律从 CMakeCache.txt 提取**，不能硬编码版本号（插件更新后会变）
3. **CubeProgrammer CLI 路径用 find 动态查找**，适配不同电脑和安装位置
4. **`.vscode/settings.json` 中的 `${env:CUBE_BUNDLE_PATH}`** 仅在 VSCode 集成终端中有效，外部 bash 拿不到
5. **Release 配置**：如果 `build/Release/CMakeCache.txt` 不存在，需要先运行 `cmake --preset Release`
6. **CMakeCache.txt 丢失**：如果编译报错且 CMakeCache.txt 不存在，说明 Debug 配置被清除了，需在 VSCode 中重新运行 CMake Configure（`Ctrl+Shift+P` → `CMake: Configure`）
7. **此 Skill 可跨项目复用**：只需在步骤 0.1 中修改 `PROJECT_ROOT` 即可

## 编译错误诊断

全量 bu​ild 输出包含两种诊断信息：

### 编译期错误（gcc）
```
D:/path/to/file.c:234:3: warning: implicit declaration of function 'xxx'
```
→ 精确到 **文件:行号:列号**，可直接跳转修改

### 链接期错误（ld）
```
ld.exe: CMakeFiles/XXX.dir/Core/Src/main.c.obj: in function 'main':
.../main.c:234: undefined reference to `xxx'
```
→ 精确到 **目标文件、函数名、符号名**，用于排查缺失的实现或库

增量编译（ninja）只重编译修改过的文件，未改动的 `.obj` 缓存复用，编译速度很快。
